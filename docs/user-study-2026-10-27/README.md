# Simulated user study, 2026-10-27 (v0.3)

Two simulated PhD users spent an hour each with the site, alone, then discussed it. The personas were written to differ: an applied remote-sensing student (crop mapping, not a statistician) and an ML student building a foundation model (statistically literate, no EO domain knowledge). Each had concrete questions and had never seen the site.

- `amara-crop-mapping.md` — which model to try first, which benchmarks reviewers accept.
- `ben-fm-builder.md` — a reliable, non-redundant 8–10 benchmark suite; baselines; how many seeds.
- `discussion.md` — their joint ranked list of improvements, the bugs both hit, and a verdict.

Headline: the site answered the benchmark question for both and the model question for neither; the volume of information is not the problem, the defaults are (what is on the first screen, the column order, the default sort). Bugs from section (b) of the discussion were fixed the same day; the ranked improvements are the next design pass.
